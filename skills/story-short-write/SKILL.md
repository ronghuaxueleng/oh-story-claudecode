# story-short-write：短篇网文写作

本 skill 只运行下文列出的正式流程、正式产物和正式脚本。未列出的过程、回执、侧车或脚本一律不得读取、创建、恢复或作为门禁条件。

## 连续执行终止硬闸

用户明确要求自动连续执行时，进入 `persistent_execution`。初稿停靠前，阶段完成、文件多、耗时长、脚本可修复错误、进度汇报和单回合容量都不是合法停止理由。

- 禁止调用 goal 机制暂停或续跑。
- 禁止以 final 交付阶段报告、要求用户回复“继续”或发送空白 final。
- 中间更新后必须立即继续工具调用或写作。
- 当前门禁失败只停止下游生成；必须留在当前阶段修复。
- 任何终止型回复前必须运行 `validate_continuation_gate.py`。
- 只有用户明确叫停、连续三轮仍不可恢复的真实外部阻断、初稿强制停靠三类原因可终止。

初稿停靠固定命令：

```bash
python3 "$SKILL_ROOT/scripts/validate_continuation_gate.py" \
  --project-dir "{项目目录}" \
  --reason initial_draft_stop \
  --platform zhihu
```

输出不是 `continuation_gate: passed` 时，禁止终止型回复。

## 定位与边界

本 skill 负责起盘、换链、细纲、正文和定点回炉。不把拆书、扫榜、整篇去味或 skill 公共规则维护混入写作主流程。

- `story-short-analyze` 负责拆书和来源账本。
- `story-short-write` 消费来源资产并完成新书。
- `story-deslop` 只在初稿停靠后按用户授权运行。

完整边界见 [skill-boundaries.md](references/governance/skill-boundaries.md)。

## 全新开书隔离

用户要求全新开书时，只允许读取：

- 本轮明确指定的原始样本及其同名拆文目录。
- 本 skill 的 `SKILL.md`、`references/`、`scripts/` 和通用题材规则。
- 本轮新建且未被其他书使用的项目目录。

禁止读取任何旧写作项目的设定、大纲、正文、回执、profile 或所谓流程模板。用户未逐本点名辅助书时，只做文件名级发现，再选择最小辅助集合；未选中的内容禁止读取。

正式开始前列出 `allowed_read_roots` 与 `forbidden_project_roots`。误读其他项目后必须从未污染的新目录重新起盘。

## 锁名与目录

书名必须在 `题材承诺 / 主卖点 / 核心情绪 / 付费期待` 清楚后锁定。用户未指定书名时，在模型内部生成 8-10 个候选，不另建命名回执。候选形态服从题材和目标平台，不强制塞入短意象名，也不限制完整因果句数量；至少从关系伤害与反制、身份翻面、反常事件与不可逆代价、独有物件或职业悬念中选择三种真正适合本书的机制。

强情绪短篇先做无简介冷读：只看书名，读者必须能立即看见至少一项具体关系或伤害动作，并对后果、身份答案或异常原因产生一个可复述的问题。只剩职业术语、抽象意象、人物称谓或后段动作的名字，即使声韵顺口也不得锁定；从某一节的标题、终局台词或题材隐喻直接抽出的书名，必须同时补出前因、代价或身份反差，否则视为“章节节点冒充书名”。

书名优先公开一个高价值前提，再保留下一层更值钱的问题。不能为了避剧透把初恋、替身、失踪、手术、离婚、死亡、罪证等真正卖点全部藏掉，也不能把所有反转写成剧情摘要。`失去/离开/听不见以后，他才爱、后悔或珍惜` 一类只有迟到情绪、没有本书独有关系或事件的句子，仍视为泛化模板。

每项事实必须能由当前设定直接支持；禁止为吸量虚构下跪、怀孕、死亡、出轨、重生等情节。用户提供的书名案例和拆书名只用于抽取吸引机制与形态分布，禁止复用其语序、标点、句壳或只替换名词。用户明确要求网上核验、按榜单起名或评估点击力时，调用 `story-short-scan` 采集公开样本与可见信号；普通开书不把扫榜增设为强制流程。

重要角色命名必须默认区分男女：男主、女主、旧爱、配偶、情敌和承担关键关系功能的配角，在候选阶段就要做“姓名单独冷读”和“姓名放入首句冷读”。性别会影响三角关系、婚姻关系、追妻/追夫方向或读者站位时，禁止使用高歧义、中性到足以把男女读反的姓名；不得等正文写完、等读者反馈或靠中段“他/她、丈夫/妻子”补救。

命名硬闸固定为三步：一，单独看姓名，判断普通读者最可能读成男性、女性还是无法判断；二，把姓名放进“我的妻子/她的丈夫/他的旧爱”等首现句，确认关系角色和性别不会冲突；三，把男女主和主要旧爱姓名并列冷读，确认不会因名字形态让读者交换性别或关系位置。任一步出现明显误读，优先换名；只有题材确实需要中性姓名时，才允许保留，并必须在首次出现的同一句完成姓名、性别和关系角色绑定。

男女姓名要有可感知的区分度，但不靠刻板标签凑数：可以通过常见使用倾向、字形组合、称谓和首现动作共同建立性别，不要求每个名字都带固定“男字/女字”。禁止同一核心关系组全部使用中性姓名，也禁止用一个姓名既指男性又指女性后再靠代词强行解释。

评分：冷读点击欲 30、核心卖点与关系辨识 25、信息差与付费期待 20、事实准确及正文可兑现 15、题面独有性与结构原创性 10。冷读点击欲低于 24、核心卖点与关系辨识低于 20、事实准确非满分、表层仿写风险非低或任一硬检查失败，禁止锁名。最终候选若仍需读简介才能解释“为什么值得点”，立即淘汰并从卖点层重起，不做句面润色。

锁名后用一条命令完成校验、原子创建与复验：

```bash
python3 "$SKILL_ROOT/scripts/validate_project_directory_name.py" \
  --project-dir "{工作区}/{小说书名}" \
  --title "{小说书名}" \
  --create-new
```

目标路径已存在时必须换名，禁止覆盖、复用、备份或移动已有路径。项目目录 basename 必须与书名逐字一致。

## 来源角色

项目配置是来源边界唯一真源：

- 主体原文独占正文声线，供应完整 P 拍、E 拍、情节/情绪骨架和表演颗粒。
- 辅助来源只供应 `selected_bids` 中明确选中的 P 拍机制。
- 辅助来源不得供应声线、句式、语气、对白嘴型、E 拍或人物壳。
- 来源路径、角色、SHA、profile 和辅助边界写入 `项目写作配置.json`，不另建读取证明。

项目配置人工填完后直接运行来源策略脚本。脚本在目标不存在时从主体 profile 初始化项目 profile，
再写入辅助边界；单书主链不得先单独生成或融合项目 profile：

仿写默认使用 `length_policy.mode=source_anchored`：细纲总上限、正文总量和数字节数都以主体原文为锚，比例不得超过 1.25。它是全书上限，不是必须写满的配额，也不设置迫使补字的下限。颗粒度只按全部 P/E 拍、SF 必经动作、情绪、场面、六维与局部说明段表演颗粒逐项 100% 兑现判断，漏一项即阻断，不得用正文或区域字数估算颗粒完整度。只有用户明确要求扩写时，才可切换 `explicit_expansion`，同时记录 `authorized_by_user=true`、用户要求和新的比例；不得凭“情节完整”自行扩容。

```bash
python3 "$SKILL_ROOT/scripts/apply_project_profile_policy.py" \
  --config "{项目目录}/写作资产/项目写作配置.json"
```

主体拆文目录缺少 `写作资产/来源成文脑图.json`，或脑图依赖 SHA、顺序、逐项内容哈希失效时，停止写作主链并回到 `story-short-analyze` 完成正式 finalize。写作 skill 不就地修补拆文资产，也不回退其他合同。

## 保留层与 P 拍换芯

主体原文的完整层级必须保留：故事核与关系命题、关系/情绪母线、BID 顺序及进入/退出位置、全部 E 拍的内容烈度与原序、全部 SF 六维成文颗粒，以及主体 P 拍的数量、原序和承重槽位。

只替换主体 P 拍的可见事件内容。每个来源 P 拍必须一对一改造成目标 P 拍；保留“这一步必须完成什么”，替换人物身份、关系壳、职业领域、现场、触发方式、物件、证据、控制权实现和现实后果。禁止把“颗粒全保留”解释成原事件换名复刻。

默认禁止检索或使用社会热点材料。只有用户在当前任务中明确要求使用热点替换事件时，才按各 BID/E 拍的压力机制检索近 30 天的非政府社会新闻或网络热梗；没有合适机制时最多扩到 90 天。不得使用浏览器或 CDP，也不得使用通用搜索引擎、新闻搜索或聚合搜索结果；只能直接访问大型新闻门户、内容社区或社交平台的公开热榜、话题页、当事方页面和报道页。禁止使用政府部门、监管机构、政务网站以及纯政策/会议通稿；候选材料必须有热榜、跨媒体跟进、平台讨论或当事方回应之一的可见热度证据。材料只供应制度压力、职业规则、舆论机制、证据形态或现实后果，不供应声线，也不得复制真实人物、新闻/热梗原句或完整时间线。

用户未明确要求热点时，不检索也不注入热点，目标事件只从新书设定、虚构现实规则和已授权辅助机制中重建。用户明确要求时，再读取 [P 拍换芯与按需热点](references/governance/p-beat-hot-news-replacement.md)；热点机制和事实/虚构边界直接写进对应目标节点及 P 拍的人工改编判断，不新增新闻回执、素材侧车或临时脚本。达到当前最低合格材料数后立即停止扩搜；材料锁定后只调整实际绑定的目标 P 拍，不得借热点重推全书 P/E 映射或延迟细纲落盘。

## 唯一正式流程

### Phase 1：设定与细纲

顺序完成 `设定.md` 和 `小节大纲.md`。设定完成后逐拍重建目标 P 拍；只有用户明确要求热点时，才在定稿细纲前按 BID/E 压力机制检索热点并注入目标事件。`小节大纲.md` 必须按导语、连续数字节、尾声的正式区域顺序，按每批 1-2 个相邻区域直接写入同一个正式文件；不足一批时写完剩余区域。每个区域除主事件和细拍外，必须写清 `入场状态` 与 `离场状态`：只记录人物位置、关系站位、关键物件/权限、已知信息和未闭合压力的变化，不重复抄写设定。批次只用于锁定已落盘真源和控制上下文，不得把一个区域拆成多个行政阶段，禁止退化成每个区域一次独立编辑，更不得在文件外累计第二套完整本 P/E 重映射；禁止创建分节草稿、临时细纲或临时合并脚本。

每批直接在正式大纲文件中落盘，不以内存候选、临时文件或复制文本作为真源；落盘后立即运行官方 `preflight --allow-partial`，只核对当前已落盘区域的结构、状态字段、来源连续前缀、顺序和绑定完整性。下一批只读取当前区域所需的主体原文行域、来源层、上一批离场状态和当前设定，不得每写一个区域就重读全书账本、profile、主体原文或热点页面。每条 `细拍拆分` 首次落盘时必须在行尾写隐藏的来源覆盖注释，注释只登记 ID，不重抄来源内容：

每个细拍首次写入前先完成同节点语义对照，禁止写完全文后再靠审计猜回：P 拍逐项核对 `action / control_change / information_change / consequence`；E 拍逐项核对 `content / trigger / relationship_position_change / reader_effect / intensity`，来源一整拍必须由当前单一目标节点完整承接，不得按相邻序号顺手分配、拆给前后节点或只保留情绪名；来源层逐项核对层型、进出关系、叙述距离、每条 `must_preserve_in_target` 和六维 active/inactive。目标节点写不下整拍或整层时，当场拆改目标施工内容再落 `source-map`，不得先登记 ID 占位。

同一次核对只额外保留两类紧凑输入：每个 P 拍选择至少三个合法换壳维度；每个来源层选 1-3 条行域内原文短引句。合法 P 维度固定只有 `actor / relationship / setting / object / conflict_mechanism / information_mechanism / consequence`。禁止自造 `control_mechanism` 等近义字段；正式脚本会在 preflight 阶段给出最接近的合法字段提示。E 五字段、P 四项承重以及层拓扑/规则/六维的目标实现都已存在于当前细拍与显式绑定中，后续只允许确定性展开，不再人工重复抄写。

```md
- 细拍拆分：目标现场施工内容 <!-- source-map: P=P-001; E=E-001; SF=SF-00A#1; L=SF-00A-L01 -->
```

- `P`、`E` 各拍在全书只能出现一次，且必须与来源同序。
- `SF` 使用 `SF-ID#步骤序号`；同一步跨多个目标节点时允许重复，但不得倒序。
- `L` 使用来源层 ID；一层跨多个目标节点时允许重复，但不得换序。
- 某目标节点不承接 P 或 E 时可省略对应字段，但每个目标节点至少承接 P/E/SF步骤/来源层中的一项。
- 注释不进入目标节点正文证据，不写入最终正文，也不算新增侧车或第二人工真源；Phase 2 映射只能由这些注释确定性派生。

每个批次先运行：

```bash
python3 "$SKILL_ROOT/scripts/manage_target_prose_map.py" preflight \
  --project-dir "{项目目录}" \
  --allow-partial
```

批次预检只允许当前已落盘内容构成主体来源账的连续前缀，不得跳拍、并拍、倒序或提前写入后续来源。全部导语、数字节和尾声落盘后，再运行不带 `--allow-partial` 的完整 `preflight`；`preflight` 通过前禁止 `init`。任何漏拍、一个节点并多个 P/E、SF 漏步、来源层漏层、状态缺失或倒序都回到当前正式文件修复，不另起内存版本。细纲必须包含导语、连续数字节和尾声；每个区域至少写清：

- 主事件、子事件和逐条细拍。
- 情绪变化、读者新增信息、钩子、物件。
- 动静、对白密度、目标字数和场面单元。

细拍和场面单元必须能承接主体 SF 的逐层来源拓扑，不能只抄剧情功能。颗粒标准不是“人物 + 动作 + 物件 + 反应”组件清单，也不默认把概述扩成现场：来源层是 `live_scene` 才必须提供可连续落笔的现场载体；来源层是 `summary_transition / public_discourse / institutional_result / rumor_afterword` 时，目标也保留相同叙事距离、粗跳幅度和断口。禁止把多种来源层型统一压成 `某人陆续提交材料 / 经过数月 / 最终承担责任` 的同一种流程说明，也禁止为了显得具体而把原文的一句急刹扩成证据流水账。

数字节密度必须迁移主体原文的段落呼吸。写前放行会读取主体原文的连续裸数字或带点数字节号，以主体节均非空白字符、主体节数和细纲目标字数计算最低合理节数，同时校验全书目标上限与数字节数上限；禁止把主体多个完整翻刀点压进一个超长数字节，也禁止在未获授权时把短篇骨架扩成中篇。

细纲的目标字数只用于写前配重、全书体量上限和分节密度判断，不是正文逐节硬门禁，也不得用于估算是否发生颗粒压缩。终审按 P/E 拍、完整 SF 表演链、局部说明段表演颗粒、六维和声线完整度逐项判断，并只以主体锚定的全书上限拦截失控扩写；不得因实际字数偏离单节目标而补描写、加回忆、重复情绪或删除必要现场。

### Phase 2：唯一目标成文脑图

拆书 finalize 已把原文、BID、全部 P/E 拍、SF 表演链和文字层编译为主体 `写作资产/来源成文脑图.json`。来源脑图只保存行号、层型、进出关系、叙述距离、六维、保留规则和内容哈希；大段原文运行时按行号读取，不重复抄入项目。

项目只维护 `写作资产/目标成文脑图.json`。目标节点可由带 `source-map` 声明的 `小节大纲.md` 解析，也可直接接受含 `source_refs` 的用户 JSON 脑图。脑图必须全量记录：

1. 主体全部 P 拍和 E 拍的一对一目标节点。
2. 每个 SF 全部必经步骤的目标表演链。
3. 每个来源文字层的目标节点，并保持层序、层型、进出关系和叙述距离。
4. 与 P 拍同序的事件壳替换判断；每拍至少确认人物、关系、场域、物件、冲突机制、信息机制、后果中的三个替换维度，并分别填写 `action / control_change / information_change / consequence` 的目标实现。禁止用一组维度和一条总评批量确认全书 P 拍。

先做只读预检，再初始化。默认紧凑主链把全量 P 维度和全量来源层短引句同时交给 `preflight`；它在目标脑图创建前完成字段名、全量同序和引句行域校验。`init` 复用同一紧凑输入，把细纲中的人工来源声明、P 维度、E 单节点确认和层引句确定性编译进目标脑图，不按行号、字数、相邻 P 拍或区域范围猜测语义：

```bash
python3 "$SKILL_ROOT/scripts/manage_target_prose_map.py" preflight \
  --project-dir "{项目目录}" \
  --dimensions-json '{与来源 P 拍同序全量对应的维度数组 JSON}' \
  --layer-anchors-json '{与来源层同序全量对应的 1-3 条原文短引句 JSON}'

python3 "$SKILL_ROOT/scripts/manage_target_prose_map.py" init \
  --project-dir "{项目目录}" \
  --dimensions-json '{同一份 P 维度 JSON}' \
  --layer-anchors-json '{同一份来源层短引句 JSON}' \
  --derive-emotions-from-outline

# 用户提供 JSON 脑图时改用：--mind-map "{脑图.json}"
```

初始化后，P/E/SF/层映射不得在 JSON 中另维护一套版本。默认主链到此不再设置一次逐字段人工复核；P 四项承重、E 五字段以及层拓扑/规则/六维都由大纲的显式单节点绑定、当前细拍内容、P 维度和来源层短引句确定性展开。只有旧项目续跑或局部人工推翻默认展开时，才使用下面两个增量覆盖接口：

```bash
python3 "$SKILL_ROOT/scripts/manage_target_prose_map.py" confirm-event-shells \
  --project-dir "{项目目录}" \
  --reviews-json '{"P-001":{"target_id":"T-opening-001","dimensions_changed":["actor","setting","object"],"function_reviews":{"action":"本拍目标动作的具体实现","control_change":"本拍控制变化的具体实现","information_change":"本拍信息变化的具体实现","consequence":"本拍现实后果的具体实现"},"adaptation_decision":"本拍专属换壳与热点事实边界"}}'
```

完整覆盖接口仍接受逐 E、逐层人工复核；紧凑覆盖接口则只接受 `--dimensions-json`、`--derive-emotions-from-outline` 和 `--layer-anchors-json`。紧凑展开的人工真源是已经逐字段核对后才落下的当前细拍与 `source-map` 绑定，脚本只改变数据形状，不生成新语义判断。短引句只证明已回读该层，不能替代完整行域：

```bash
python3 "$SKILL_ROOT/scripts/manage_target_prose_map.py" confirm-fidelity \
  --project-dir "{项目目录}" \
  --emotion-reviews-json '{逐 E 拍五字段显式复核 JSON}' \
  --layer-reviews-json '{逐来源层拓扑、规则与六维显式复核 JSON}'
```

映射完成后封存：

```bash
python3 "$SKILL_ROOT/scripts/manage_target_prose_map.py" validate \
  --project-dir "{项目目录}"
```

细纲、脑图或来源资产变化时只能运行正式增量重绑。`rebind` 重新读取当前 `source-map` 声明确定性生成 P/E/SF/层映射；目标 P 节点内容发生变化时，只使对应事件壳人工确认失效，不得按行号猜测迁移，也不得编写临时迁移脚本：

```bash
python3 "$SKILL_ROOT/scripts/manage_target_prose_map.py" rebind \
  --project-dir "{项目目录}"
```

仅对本规则生效前已经初始化、尚未封存的旧项目，可一次使用 `migrate-legacy-source-refs`。它读取旧项目已人工复核的绑定及审阅者明确覆盖，先按新合同全量校验，再原子写回细纲隐藏声明并立即 rebind；新项目、已封存项目和存在未知绑定的项目禁止使用。该迁移不是正常写作阶段，不得用于绕过 `preflight`。

P/E 不得漏拍、并拍或倒序；P 四项承重不得用同一句结论批量套写；E 五字段不得拆散或顺移；SF 表演链不得漏步；来源全部有效正文行必须进入 SF/文字层联合覆盖，文字层不得漏层、换序、功能顺移或越出 SF 连续承载范围。任一来源层没有行域内短引句、写前保真确认缺失、目标节点内容哈希变化或仍用宽泛说明代替具体实现，`validate` 必须阻断。目标节点仍只是流程描述、结果总结或分析标签时，不能绑定现场层；先把目标节点改成可连续落笔的施工颗粒，再运行 `rebind`。辅助来源只供应已授权 P 拍机制，不接入 E 拍和文字层。

### Phase 3：正文放行与直接写作

主体声线直接由主体原文、主体 profile 和来源脑图的逐层颗粒约束；情绪由目标脑图的 E 拍映射约束；可见事件只来自已经换芯的目标 P 拍。目标脑图不存在、未封存或已失效时，正文放行必须阻断。

正文前只运行：

```bash
python3 "$SKILL_ROOT/scripts/validate_streamlined_write_release.py" \
  --project-dir "{项目目录}"
```

通过后直接写入 `正文.md`：首行用 `# 《书名》`，随后写导语，再按 `1.`、`2.` 直到 `N.` 的知乎纯数字分节顺序写正文，尾声并入最后一个数字节。可以分批编辑文件，但不得为每节创建“开始/暂存/验收/提交”行政流程。

写每个区域前，只从目标脑图读取本区域的 P/E、SF 步骤和层 ID，先核对该层写前复核里的原文短引句，再按层 ID 回查来源脑图并完整读取对应原文行域；不得把短引句当成该层全部内容。按来源层顺序施工，只替换事件壳：现场仍是现场，概述仍是概述，插嘴仍放在对应层间，急刹和冷尾不得扩写或提前。目标节点无法承载某层时，先修目标节点并正式 `rebind`；不得临场把缺层改成流程总结。一个 SF 跨多个区域时，从首个落点到最后落点视为同一连续写作单元。检查发生在正文上，不另建逐节证明。

### Phase 4：紧凑正文覆盖终审

全文完成后只建立 `正文覆盖回执.json`。静态的区域六维、SF 整链和来源层对象都保留在两张脑图中，终审不再重复三套内容；回执只保存两张脑图与正文 SHA、区域覆盖、全部来源层的正文逐字引句、人工结论以及缺失/倒序/层型错配异常。

人工逐层显式填写 `realized=true / topology_preserved=true`，并分别为层型、进入、退出、叙述距离、无功能顺移、每条来源保留规则和六维提供专属正文引句与结论；同时对全部目标节点逐节点确认颗粒。来源全部 P 拍必须逐拍显式提交五个保真布尔，并为 `action / control_change / information_change / consequence` 分别给正文引句与结论，脚本不得自动全置真。来源全部 E 拍还必须逐拍确认 `content / trigger / relationship_position_change / reader_effect / intensity` 及 `whole_beat_in_one_node=true`，每字段有绑定节点内的专属引句与结论。目标节点只是写到了、情绪相近或事件更合理，都不能替代对应拍位保真；宽泛引句不得替整层、多个字段或多个节点过检。任何漏 P/E、漏层、漏节点、功能顺移、换序、改层型、失效引句或异常未清零都阻断封存；发现问题先改正文，再运行 `audit-init` 增量刷新，仍有效的逐项判断按绑定和引句保留。

## 写作硬标准

- 定点回修必须最小化：用户指出一个具体字、词、短语或句子的自然度问题时，只处理该问题及其必要的标点、搭配变化，不得顺手重写相邻句、动作、物件、事件或声线。用户没有要求“顺便优化”的内容视为冻结，不得扩大回修范围。
- 用户对表达作出明确取舍时，以用户判断为最终验收标准：用户明确说某个版本“更顺”“更像人写的”或要求恢复此前版本，必须原样保留或恢复该版本，不得用抽象语法偏好、书面简洁或模型自己的初始判断反驳。
- 正文语言自然度默认检查，不等用户指出：每句落笔时都要检查虚词、口语停顿、人物当下说法和主体声线；“的”能让句子更顺、更像人在说或更符合人物语气时必须保留，不得机械删减。动作—物件自然度也必须在写作时同步检查，不能等正文完成后再靠用户抓错。
- 连接虚词必须确认功能后再取舍：每个“便、就、又、也、却、才、还、仍、已经、于是”等可有可无的词，都要判断它是在补时间顺承、动作结果、因果、转折、重复或语气落点；先做“有词/无词”对读，再按人物口气和主体声线决定。不能因为句子语法成立就删掉承担顺承功能的“便”，也不能为了显得顺口机械添加虚词。
- 句间因果和转折必须有真实承接：使用“可、但、却、因此、所以、便、才”等连接词前，必须确认前句确实构成后句的原因、条件、转折或时间触发；不能用“可”把两个仅仅相邻、没有逻辑关系的事实硬粘在一起。若情绪推动后续动作，应补最小可见中间状态，如脸上发烫、不敢抬头、撞上视线后躲开，不补作者式解释。
- 语言问题要按实际问题精确处理：检查“的”字时只比较“有的/无的”的朗读、停顿、口气和语义，不得借此改写无关的动作、物件、事件或整句；发现动作问题时才改动作，发现虚词问题时才改虚词。
- 抽象被动动作要补足必要对象和载体，但不得过度补写：如“我就会被划掉”“他被拿走了”“她被处理了”确实让人无法判断改变了什么时，必须补明名字、资格、权限、位置或物件；如果上下文已经明确承载位置，简洁的“压在下面、放在里面、留在门口”等省略反而更像人话，不得为了形式完整硬加“文件堆最下面”等解释性名词。
- 静态传播段要把照片内容、可识别特征和发布动作串起来：不能把“发照片到”“某人特征，清清楚楚”“他给照片配文”等成分机械并列；发布对象用“把照片发到/发上平台”，照片中的特征用“被拍得清楚/也清晰可见”，发布者在有多个男性角色时必须点名，避免传播链出现搭配断裂或指代跳转。
- 关键事实首次出现必须说清：疾病、伤情、职业资格、法律状态、证据性质和其他会推动人物选择或读者判断的事实，不能只写“出了问题、结果不好、被处理、出了事故”等空泛结果，必须在首次承担剧情功能的位置交代具体对象或名称；不得让读者依赖设定、大纲或后文补回关键事实。
- 身份履历不得凭空补写：职业资格、合伙人/成员名单、被除名或被替代经历、法律与财务状态等，必须先在设定、细纲或正文前文建立，才能在对白或叙述中作为既定事实使用；若当前只成立“项目失败、欠款、位置被觊觎”等事实，不得擅自升级成“曾任某身份后被某机构除名”。缺少前置依据时，改用当前已成立的可验证事实，不靠对白硬塞新履历。
- 关键场域首次出现必须完成最低锚定：涉及人物关系、情绪转折或动作承重的“现场、房间、门口、那里、楼下”等泛场域，首次出现时必须补出必要限定，如“项目现场、事务所办公室、共同宅院门口、医院手术室”；已经由前文明确锚定后，后续才可自然省略。不得让读者等后文猜“现场”到底是什么现场。
- 人物指代清晰度默认检查：连续句、叙述句和对白中的“他/她/他们”必须能让读者立即确认所指人物；同一段、前两句或当前场面存在两个或以上同性别人物时，涉及关键动作、病情、关系变化和对白对象，必须优先直接点名，不得依赖读者回溯猜测。
- 人物指代先行词必须显式绑定：每个关键代词都要能在当前句或前一句找到唯一明确先行词；若存在两个可成立的候选，即使语法上“看起来能通”，也必须改为姓名、身份或关系称谓。正文开头、导语、章节转场、三角关系场、病情节点、高潮和结尾一律按高风险位置处理。
- 同一短场景内代词不得快速换指：连续两三句或同一轮对白中，同一个“她/他”不能先指罗岑、再指贺明棠，或先指季临川、再指江砚；一旦指代对象切换，必须直接使用姓名、身份或关系称谓。目光、递交、拒绝和依赖等关键动作也要把具体对象写出来，不能只用“没看她、只看着他”让读者回溯。
- 同场代词必须先做实体锁定：写作或回修含两个及以上同性别人物的场景前，先列出当前在场人物及其关系位置，逐句核对“他/她”唯一指向；同一句或同一轮对白若需要让两个代词分别指向不同人物，直接改用姓名、身份或关系称谓，不能以读者“应该能猜到”为放行理由。交付前必须对该场景再做一次代词抽查。
- 明确先行词时不机械重复姓名：同场存在两个同性别人物，不等于每句都必须重新点名；若前一句已用姓名或身份唯一绑定人物，下一句仍连续指向同一人，且没有视线、动作或话轮换主，可以保留“她/他”及其所属身体部位，如“我看着她的眼睛”。只有出现两个可成立候选或发生指代切换时，才必须再次点名。
- 同一主语的连续动作可合并但不能牺牲指代：同一人物紧接着完成多个动作时，可以合并为一个连续句，只保留一次姓名并用“又、随后、紧接着”等词连接，避免重复点名；但场景中存在同姓别竞争人物时，不得把姓名直接省成“她/他又……”，必须保留姓名或用合并结构确保主语唯一。
- 主角身份与性别必须在开头建立：第一人称“我”不会自动暴露性别；“我爱的人是她的姐姐”只能说明被爱者性别，不能说明“我”是男是女。导语或首屏必须用“丈夫、妻子、男友、女友”等明确关系角色，或用不依赖标签但能确认性别的现实动作建立主角身份。读者在读完首屏后若仍不能回答“谁在讲、与谁是什么关系、主角性别是否影响关系理解”，必须回炉。
- 主要角色姓名必须做性别辨识度冷读：姓名本身可能偏中性或诱导反向判断时，首次出现必须同时绑定性别和关系角色，例如“我的妻子贺明棠”“她的丈夫江砚”；不得先只报姓名、连续使用“我/她”让读者自行猜测。强情绪关系文中，女主、男主、旧爱和第三人若性别判断会影响关系理解，优先使用性别辨识更清楚的姓名，或在首屏完成明确锚定。
- 姓名冷读不能被后文补救：不能以中段“丈夫、妻子、他、她”等称谓为首屏身份缺失开脱；正文第一句或前两句就必须让读者知道叙述者是谁、主要伴侣是谁、双方性别和关系位置是什么。姓名、代词、称谓三者发生冲突时，以首屏明确关系为硬优先级。
- 男女姓名区分是默认写作要求，不只是补救措施：每次新建人物、改名或换壳时，都要检查姓名在男女角色之间的辨识度；只要名字可能让读者把男女主、配偶或旧爱读反，就必须在落盘前换名或补首现身份，不得把“后面会说明”当作合格理由。
- 对白自指不得使用第三人称代词：说话人质问自己是否被告知、自己是否被看见或自己是否被选择时，使用“告诉我”“看着我”“选我”；“为什么不告诉她”“你为什么不看她”这类句子若指向说话人，直接判为指代风险。
- 省略指代不能由主体声线豁免：主体原文的短句、跳跃和省略可以保留，但不能保留会改变人物归属或让读者停下来猜人的省略。声线保真服从人物可辨认性，不得把“像原文”当作指代清晰的替代证明。
- 正文落盘前必须做一次人物指代专项通读：逐句圈出“他/她/他们/这个人/那个人”等指代，核对唯一先行词、当前场面位置和对白说话人；发现任何需要回看两句以上才能确认的代词，必须在落盘前改清。专项通读不是格式校验，不能以正文覆盖回执或颗粒审计代替。
- 正文落盘前还必须做一次“首屏身份冷读”：只看标题、导语和第一节开头，确认主角性别、婚姻/恋爱角色、叙述关系和关键第三人均可直接回答；不得把性别和角色信息拖到中段再补。
- 首屏身份冷读必须包含“姓名反向误导测试”：分别只看主要角色姓名和首屏前两句，检查是否会把男主、女主或旧爱性别读反；若姓名单独容易误导，首现句必须补关系角色，必要时更换姓名，不得把错误留给读者自行纠正。
- 首屏命名放行必须确认：主要男女角色的姓名不会互相误导；首句或前两句明确写出至少一组“男性角色 + 女性角色 + 关系位置”；旧爱若在导语出现，也必须让读者直接知道其性别和与主角的关系。
- 回修前先锁定“目标片段”和“禁止牵连改动”，回修后必须检查差异只落在目标片段；发现无关行被改动，先恢复无关改动，再做格式或终审校验。不得用一次大范围润色掩盖定点修改。
- 正文唯一声线来自主体原文。保留主体的句间转折、功能词、叙述距离、即时主观声音、对白轮转和段落呼吸。
- 主体全部 SF 的六维颗粒必须随 P 拍自动落到目标区域；写作和终审都不得只使用 profile 的书级汇总声线。
- 故事核、关系/情绪母线、BID 进出位置和全部 E 拍必须完整保留；启用热点时也不得改写上层情绪因果。
- 主体 P 拍只保留等量同序承重槽位，每一拍都必须换成新的目标事件；原人物、职业、物件、现场和完整事件壳不得回流。
- 用户未明确要求热点时禁止检索、读取或注入社会热点材料。明确启用后，只允许非政府社会新闻或有可见热度证据的网络热梗；材料只供应目标 P 拍的现实机制，必须可追溯、在检索时不超过 90 天并完成去标识化；不得扩成游离支线。
- 不复制主体的专名、核心物件、完整关系壳或原句。
- 主体 P 拍槽位与 E 拍按合同原序兑现；辅助机制只能叠加，不能替换主体上层骨架。
- 强情绪必须改变人物期待、行动冲动或现实位置，不靠情绪词汇报。
- 关键关系动作要有最小可见情绪承接：松手、转身、递还、推开、离场等动作如果承担关系断裂或态度翻转，不能只写干巴的结果动作；应在不扩写的前提下补一个能被看见的状态或节奏，如“看着她的眼睛，怔怔地松开了手”“停了一下才转身”。这不是要求每个动作都加情绪副词，状态必须服务于当前关系变化，不能堆叠心理标签。
- 追妻必须由失去控制权、接近资格和真实代价推动，不靠突然自白。
- 女主离开必须落到可见决定、物件处置、法律/工作/联系权变化。
- 高潮至少满足两项：压后信息释放、发生在最该公开的场面、让前文意义整体变狠。
- 结尾保留后果和新位置，不做空泛价值总结。
- 多动作、多信息或视线换主的长句必须在自然换气点拆开；单一身体、感官或话轮链可保留长句。
- 动作—物件自然度必须逐句过检：动词要符合物件的实际可操作方式、受力方向和使用场景，不能为了画面感把不需要固定的物件写成被“按住”。例如签字笔应使用“握着、拿着、落笔、共同签字”等动作；“按住”只能用于纸张、门、肩膀、手腕等确实需要被压住或制止的对象。
- 物件损坏必须有现实受力来源：普通人物的握、捏、拿不能无因造成玻璃开裂、金属变形、家具断裂等超出常识的结果；强情绪要通过可解释的磕碰、摔落、脱手、撞击或施力过程表现。除非设定明确允许超自然或特殊力量，否则禁止用“捏裂玻璃”一类异能化结果替代人物失控。
- 连续动作链必须逐步交代受力来源、动作方向和可见结果：前一句造成的倒地、后退、碰撞、脱手或位置变化，必须能由后一动作直接承接；不能写成“扯断线缆，人物突然撞到展台边”这类缺少中间受力或移动过程的跳接。需要时补出“支架倒下逼退”“转身推到台沿”“后腰撞上台沿”等最小承接，不得为了补因果扩写成分镜清单。
- 传递动作必须区分对象与落点：物件是交给人时，默认使用“递给、扔给、塞给、交到手里”；物件是覆盖或落在身体上时，使用“披到肩上、盖在身上、落在腿上”；“扔到身上”只有在确实要写砸中、撞上或故意制造身体冲击时才成立，不能把“扔给人”误写成“扔到人身上”。
- 抽象结果不能直接充当具体物件：不能把“失败、痛苦、后悔、关系、体面、真相”等抽象结果写成可以翻页、朗读、递交、扔掉或拿在手里的对象；需要具体动作时，必须落到“项目复盘材料、病历、协议、照片、证据、文件”等真实载体。比如“读一页自己的失败”应改为“念一页项目复盘材料”。
- 具体职业动作不能和抽象概念硬搭：签字、盖章、验收、递交、归档等有明确现实对象的动作，不能直接支配“未来、关系、体面、感情”等抽象宾语；应改写为“跟谁一起签字”“在协议上签名”“盖下自己的章”等现实口语表达。
- 身份事实和抽象评价不能硬拼：不要把“失败、落魄、可怜、没用”等评价直接压在“合伙人、丈夫、老板、学生”等身份前后，组成像系统标签的短语。需要表达羞辱或贬低时，先说清可验证的身份事实或名单变化，再用人物口气完成评价；例如“失败合伙人”优先改成“被事务所踢出合伙人名单的合伙人”。
- 姿势结果和动作方向要分清：正在移动时可用“靠过去、走到、退到、挪到”；动作已经完成、强调身体所处位置时，用“靠在、站在、坐在、退到位”；不能把表示终点状态的“靠在”机械换成“靠到”，也不能让方向词代替真实姿势。
- 称呼或态度变化必须有前置触发：使用“改口、换称呼、重新叫、立刻站队”等变化词时，前文或同句必须交代触发动作、原称呼或关系判断为何改变；否则会像流程播报。群体称呼变化要写成“见某人公开护着谁，众人纷纷改叫……”等可直接理解的因果。
- 动作目标和并列成分必须清楚：如“冷冷地看过去、抬头看了一眼、伸手指过去”等动作，若当前场面存在多个可视对象，必须写明看向谁、指向谁、伸手碰谁；并列宾语必须属于同一语义层级，不能把人物和身份、物件和结果、位置和抽象概念直接并列。比如“拿我丈夫和合伙人开玩笑”应拆成“拿我丈夫的身份和合伙人的位置开玩笑”。
- 威胁和命令句不能机械套条件句：人物当场喝止、警告或命令时，不得生硬使用“谁……就……”直接拼接结果动词，尤其不能写成“谁再……就闭嘴”。要让语气像真人发话，使用“马上给我闭嘴、别再说了、滚出去、我让你当场停下”等符合人物身份和现场力度的表达；条件关系保留，但结果句必须有自然的命令对象、语气词或行动后果。
- 对白动词支配关系必须符合口语：不能把“管我”和“我要做什么”机械揉成“管我要救谁”这类语义关系发涩的结构。表达拒绝干涉时，优先使用“我的事，轮不着你来管”“我做什么，关你什么事”等自然句式，并根据人物语气调整强弱；不得只因句法勉强成立就放行。
- 群体喝止的语气强度要完整：当人物面对多人或不止一个潜在冒犯者时，“谁再敢……”比“谁再……”更有威慑，“都马上给我……”比单独“马上给我……”更能完成群体命令；只要场面和人物权限支持，不能为了简洁删掉“敢”“都”等决定语气力度的词。
- 强势对白的并列对象必须同层：不能把人物、身份、位置和抽象概念直接揉进同一个“拿……开玩笑”结构。需要同时回应两类冒犯时，拆成“拿某人开玩笑，或者拿某个位置说事”等两个口语动作，并给出具体现场后果，如“立刻给我滚出去”，避免“谁……都……”形式完整但说起来发涩。
- 时间连词和存在表达必须分清：人物“在、也在、在场、也来了”表示出席或存在；“直到”表示时间边界，后面必须接完整的时间变化或结果，不能写成“因为某某在”前面硬加“直到”。原因句应使用“因为某某也在/也来了/在场”，不要把“直到”误当成加强语气的虚词。
- 共享物件必须写清真实动作关系：两人共同使用签字笔时，写“共同握着一支笔签字”或“手叠着手在图纸上落笔”，不得写成“按住同一支签字笔”。正文、大纲和导语都适用本规则。
- 多人物同框动作必须拆出各自的动作和位置：不能用“共同把手按在”把两个人的手、方向和空间关系揉成一个机械动作；应写成“两人一左一右把手按在蓝图上”“两人的手分别落在蓝图两侧”等可直接看见的关系。物件只是同框而非共同操作时，也不得用“共同/共享”制造虚假互动。
- 生活语言校验优先于修辞密度：凡是“动词 + 物件”“动词 + 身体部位”“人物 + 工具”的搭配，先做一次普通人能否自然说出、现场能否实际完成的检查；无法由真实动作解释的搭配必须回炉，不得以主体声线、情绪强度或比喻感掩盖。
- 虚词自然度不得机械删改：不能因为“的”在语法上可以省略，就默认删掉更自然；“每一次的项目危机”这类结构若更符合第一人称口语、停顿和主体声线，必须保留。判断以朗读顺口度、语气强调和人物当下说法为准，不以书面压缩或字数更少作为优先级。
- 不把连续现场压成一行，也不机械拆成“一句一个动作”的施工清单。

## 脚本纪律

- 定点回修不得重放无关优化：正式流程或正文回修只刷新受影响的验证与回执；不得因为一处虚词取舍，重新改写动作、物件、场面或相邻段落。任何自动修复若超出用户指定片段，必须撤销超范围结果后再继续。
- `$SKILL_ROOT` 由当前实际加载的 `SKILL.md` 路径推导，不假设安装层级。
- 已有完整命令时禁止先跑 `--help` 探参。
- 正式产物由官方脚本初始化、绑定和封口；人工字段用 `apply_patch` 小范围填写。
- 临时脚本只允许一次性只读诊断。重复性写入必须并入正式脚本。
- 同一路径上的 `export / apply / validate / seal` 严格串行。
- 续跑时复用绑定仍有效的已通过回执；上游未变更时，不重放已通过的初始化或放行命令。
- `seal` 通过后直接运行停靠闸，不加一次“保险式”格式或终审复验。
- 脚本只能做确定性解析、绑定、映射展开和校验，不得生成正文或人工判断。
- 同一语义只保留一个人工真源；下游需要不同形状时确定性派生，不再人工抄写。
