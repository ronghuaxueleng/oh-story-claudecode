# 主体原文主导首稿

本模式用于有明确主体原文的仿写、融合写作和颗粒度迁移。目标是先让正文完整长成主体原文的有效成文形状，再决定是否需要成稿去味。

## 首稿优先级

1. 题材承诺、事实与桥段顺序成立。
2. 主体原文的文字颗粒度、情绪拍序、叙述者声音和成文活性主导生成。
3. 拒绝原人物、职业、物件、原句和完整事件壳的表层复制。
4. 辅助书只供应桥段、场面和后果机制，不供应正文声线。
5. 只拦明显不属于主体原文的 GPT 污染，如规则施工稿、万能主题总结、连续解释盖章和整齐答题对白。

第 5 项按“偏离主体原文”处理，不运行去 AI 味审计，也不追求命中清零。

## 首稿禁做

初稿停靠前禁止执行：

- `story-deslop` 或系统性去 AI 三遍法。
- 轻审计、重审计、算法滑窗、人工窗口和 AI 命中清零。
- 直接心理清零、情绪词清零、作者评价清零或固定密度配平。
- 为了更“安全”而删除主体原文式的直白判断、刻薄插嘴、不体面念头、突然失态、情绪回跳和骤断短句。
- 用身体反应替掉所有直接心理。主体原文若在现场直接说“我也还是个人”“真恶心”“有钱人说话就是轻松”，目标稿允许生成同功能的新句。

## 唯一声线来源

首稿必须同时消费：

- 每节至少两组直接展开的连续主体原文句链，以及与之逐组配对的完整错误反例。
- 每节至少两组原文对白三联包：连续原文直接对白、当前人物自然口语试演、完整僵硬错例。
- 七维书级声线。
- 52 项超细文字特征。
- 成文活性层。
- 人物性格颗粒度层。
- 逐节情绪颗粒度合同。

连续句链是生成主驱动，其余层负责人物、情绪和偏移校准。它们都不是清洗表。落笔模型必须在当前上下文中直接看见原文连续句子、完整错句及正误理由，不能只看文件路径、规则摘要、特征标签或原句 ID。单句标签只回答“写完后哪里对得上”，不能代替“下一句为什么从上一句长出来”。

对白三联包单独回答“这个人到底怎样把话说出口”。主体原文必须直接展示称呼如何进入、认错或找补如何铺开、人物怎样借旧关系和第三人的处境施压、被追问后又怎样答偏。当前人物试演负责把这些口头动作移入新人物，错误反例负责拦住把细纲压成“人物调度 + 情节信息”的高效功能句。试演只校准口条，不得逐字塞进正文。

连续句链重点迁移 `具体异常 -> 具体追问 -> 错答或回避 -> 短促插嘴 -> 动作改变 -> 直接切断` 等原文真实句间关系。该顺序按所选片段实际情况裁决，不机械凑齐全部节点，也不复制原人物、物件和原句。

宏观句链之外，每节还要直接展开两组句间微关系正反例。重点不是多塞连接词，而是看清原文何时用 `而 / 却 / 但 / 可 / 反倒 / 偏偏` 把反差说出来，何时故意不接、让相邻动作自己反证。当前正文若出现“语义已转弯，句面仍平推”的硬并列，先按主体原文同类位置选择显式或隐式，再改句；不得统一补“却”制造另一种模板味。

## 停靠边界

正文全部写完后只允许：

1. 绑定并验证文字颗粒度合同。
2. 绑定并验证情绪颗粒度合同。
3. 统计字数。
4. 校验平台分节格式。
5. 确认正文文件可读。

完成后立即交给用户预览。只有用户明确要求“去 AI 味”“继续深审”或同义操作，才进入成稿清洗或审计。

## 成稿去味边界

后续去味只能删除 `draft_extra_ai_shell`，不能删除 `source_like` 的有效形状。任何修改若让脚本命中下降，却同时让直接情绪、情绪峰值、人物脾气或原文气口变弱，判定为失败并恢复原稿表达。
